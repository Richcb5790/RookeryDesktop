Hosting integrations

Docked with every place your code lives.

Connect GitHub, GitLab, Bitbucket and Azure DevOps, plus Jira and Trello for issues. Pull requests and issues show up next to the branches they belong to, and the Launchpad gathers everything waiting on you.

  • Pull requests beside branches

    Open pull requests sit on their branch labels in the graph, with description, reviewers, checks and conflicts a click away.

  • Drag a branch to open a PR

    Drop a branch on its remote and Rookery fills in your template. If the remote is behind, it pushes first.

  • Start work from an issue

    Pick an issue and get a branch named after it. The pull request that follows links back and closes it.

  • The Launchpad

    Reviews waiting for you, your open pull requests and issues assigned to you, from every account, in one tab.

Tokens are encrypted with your OS keychain and never reach the window. Git keeps using your own credential helper.

  • GitHub and GitHub Enterprise Server: repositories, pull requests, issues
  • GitLab.com and self-managed GitLab: repositories, merge requests, issues
  • Bitbucket Cloud and Data Center: repositories, pull requests
  • Azure DevOps: repositories, pull requests, Boards work items
  • Jira Cloud and Data Center: issues
  • Trello: cards

Isolate a branch

Shine a light on any branch's story.

  1. Real histories get crowded

    Seven lines of work, merges going every direction. Which one is yours, and where did it end up?

  2. Isolate it

    One click and everything unrelated falls away. The branch moves to the first lane with only what it touched: its own commits, what merged in, and where it merged out.

  3. Read the map

    The same story as a map: created from main, feature/sensors merged in, then shipped to develop and main.

  4. Trust the timeline

    Every fact says where it came from: recorded by Rookery, the branch reflog, a merge message, or inferred from the graph.

Local AI agents

Bring your own agent.
Keep the final say.

Rookery has no AI of its own and no service behind it. It hands the work to the coding agent you already use, signed in as you, and shows you what it proposes.

The rest of the toolkit

            
Everything you'd expect.
Some things you wouldn't.

          

          
    
            
  • 
              
    
                
    
                  
                  
    Submodule sync
    
                  
    Create, check out, merge, push, pull and rebase carry through every submodule. Merges go submodule-first and the parent's pointers resolve to the results. Every step is previewed, journaled, and can be rolled back.
    
                
    
                
              
    
            
    • 
            
  • Interactive rebase
    Pick, reword, squash, fixup and drop. Drag to reorder, and undo it all.
    • 
            
  • The Harbor
    Every repository you have, including ones it finds in your folders. Ctrl+Shift+H
    • 
            
  • Worktrees
    Create, lock and prune worktrees, and open each in its own tab.
    • 
            
  • Git LFS & Git Flow
    Track, lock and prune LFS files. Start and finish features, releases and hotfixes.
    • 
            
  • Image diffs
    Side by side, swipe and onion skin, for PNG, JPEG, WebP, SVG and more.
    • 
            
  • Built-in terminal
    Docked below or beside the graph, with git completions for branches, files and flags.
    • 
            
  • Profiles & workspaces
    Separate identities and accounts per profile. Fetch or clone a whole group of repos at once.
    • 
            
  • Your shortcuts
    Rebind any command. Ctrl+/ shows them all.
    • 
            
  • Undo that
    Checkouts, commits, discards, resets and branch changes can all be undone, even across submodules.
    • 
            
  • Your diff and merge tools
    Hunk, inline and split diffs built in, blame with an age heatmap, and any external diff or merge tool one click away.
    • 
          


          
    
            
  • Runs real git. Every command goes through the git CLI, so hooks, signing, LFS and credential helpers behave exactly as they do in your terminal.
    • 
            
  • Never stores git credentials. Git Credential Manager or ssh-agent handle them, and any prompt git raises is shown to you as it is.
